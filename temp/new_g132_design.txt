

1: Create a requirement sheet

    Brainstorm about what ya want your CPU to do
    Sort each point one by priority


2: Make an "ISA guide" sheet

    Start defining your ISAs corner specs (data bit width, neumann/harvard, ...)
    DO NOT define details here like instructions. Ya can start thinking about how many ya need (e.g. how many bits for opcode, how many for register addresses, ...) but you do not define the exact registers and instructions here


3: Make an ISA sheet

    Make two categories: instructions and registers (for more advanced designs also interrupts, control flags, ...)

    Brainstorm what you need for each category to satisfy your requirement sheet (e.g. instructions like ADD, RSW, ...)

    Sort them in each category by priority again based on your requirement sheets points
    Form the ISA based on your ISA guide and the sorted instructions, registers, ...
    If you have e.g. 133 instructions in your instruction brainstorm but only 64 instruction spaces (opcodes): cut down the lower priority things
    Define the instruction formats (e.g. ADD needs Trg, SrcA, SrcB and NOT needs only Trg and SrcA)
    Cluster together instructions with similar instruction formats to later reduce decoder complexity
    One method is to first sort the instructions by broad category (ALU instructions, memory instructions, program control instructions, ...) and then sort them more granular based on the used format

ISA draft:


	arithmetic:

		ADD 		A, B
		SUBTRACT	A, B
		NEGATE		A


	logic:

		AND 		A, B
		OR 			A, B
		XOR 		A, B
		NOT 		A
		SHIFT L 	A, B
		SHIFT R 	A, B
		ROTATE L 	A
		ROTATE R 	A
			for shift:
				has src 1 and 2 bc, if A=B than normal shift
				if A!=B then shift out A, shift in B

	branch:

		UNCONDITIONAL REG 		A, condition
		CONDITIONAL REG 		A, condition
		
		both branch and call, if A=PC, then address is immediate

	calling:

		UNCONDITIONAL REG 		A, condition
		CONDITIONAL REG 		A, condition



	register:

		TRANSFER 		A, B
		LOAD IMM 		A
		STORE ADDR 		A (immediate = address)
		LOAD ADDR 		A (immediate = address)
		PUSH 			A
		POP 			A
		SWAP 			A, B
		TRANSFER TO SPECIAL REGISTER 	A, B
		TRANSFER FROM SPECIAL REGISTER  A, B
		LOAD IMM SPECIAL REGISTER 		A, B
		LOAD ADDR SPECIAL REGISTER 		A, B
		STORE IMM 						A


	interrupt:

		SOFTWARE INTERRUPT



	other behaviour specifications:

		registers:
			reg 0 is PC
			others are general

		special registers:
			reg 0 model
			reg 1 cpu frequency
			reg 2 flags
			reg 4 interrupts/exeptions
			reg 5 timer controls
			reg 6 MMU start address
			reg 7 MMU stop address
			reg 8 MMU offset
			reg 9 unmasked hardware interrupt vector
			reg 10 masked hardware interrupt vector
			reg 11 software interrupt vector
			reg 12 exception vector
			reg 13 system stack pointer
			reg 14 program stack pointer
			reg 15 timer 0

		MMU:
			will add offset to current address
			will check if under or over limits
				if out of bounds, interrupt

			will use upper 8bits and 256 word pages

		interrupt behaviour:
			inject software interrupt instead of the next instruction
			add a modifier, this will tell it what to add to the PC
			this way, interrupts will trigger instantly
			do this for the exceptions as well

			separate exeptions from interrupts
				exeptions will save the PC at the moment where it happened + offset of the instruction
					example: 5 stage pipeline, 3rd is memory access, 1st is decoder
					if out of bound you save PC-3 to get the address of the instruction
					if instruction is kernel while in usermode then save PC-1

					the rest of the pipeline will be flushed, exept the instructions after the bad instruction
					then normal interrupt takes over

		cache:
			internal 2 port ram, size idk, maybe 256
			
				use real address to load pages
				load new page when program goes out
				if a load instruction is out of cache, pass through instead of loading a page
					same with store at address
					same with stack
					if store is inside the cached page, store both cache and main ram

		branch conditions:
			unconditional
			if selected register is zero
			if selected register is not zero
			if selected register is greater than zero
			if selected register is less than zero 
			if selected register lsb is 1
			if selected register msb-1 is 1
			if selected register msb is 1



	pipeline structure:
		stage 1: fetch
			load from memory, if interrupt/exeption load an interrupt

		stage 2: decode
			break down into signals that will activate the needed parts
			check registers
			check instruction and program priviledge, if bad then flush fetch
			select registers that will be loaded
				if the needed register is going to be written to,
				select that as the register input
			if the stack is needed, inc/dec it
			select immediate data if needed and inject a NOP as next into the fetch unit

		stage 3A: alu
			execute alu instruction
			write result directly to registers
			mmu will tell it if out of bounds, if yes then read/write signals are blocked
				if bad, flush fetch and decode

		stage 3B: memory access
			access memory
			write data directly to registers
			mmu will tell it if out of bounds, if yes then read/write signals are blocked
				if bad, flush fetch and decode
			check branch/call condition
				if need to jump, flush fetch and decode and change PC
